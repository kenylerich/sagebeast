## 要保留的行为

一次任务级递归包含三类角色：

1. **提议。** 根据当前 harness 和已有执行证据，提出不改变任务目标的修改。
2. **探测。** 在同一任务上执行候选 harness，记录行为差异。探测不能看到隐藏评分标准。
3. **组合。** 只根据执行对比选择或合成下一版 harness。没有证据支持的修改不采纳。

预算 `k` 有两种用法，实现前由 Q2 选择是否都支持：

- 并行：同一轮探测多个候选，再组合。
- 顺序：把上一轮采纳的 harness 和证据带入下一轮。

任务级递归结束后，经验层只保留被采纳的 harness，以及有执行证据支持的教训。后续任务可以读较早的教训，不能读本次裁判答案。

无效提议只能有限次重试，然后继承当前 harness。传输或执行失败不能被记成高分。

## 明确不保留的部分

- JobBench、LAB、WorkBuddy-Bench 的任务、数据和分数。
- OpenCode 与 Codex substrate。Sagebeast 的执行器是 DeepSeek Harness。
- Harness² 的模型供应商设置、云登录和基准安装脚本。
- 为了提高外部论文分数而做的提示词。

## 分数的含义

Sagebeast 的分数只衡量研究任务契约：是否取对数据、是否标明时间、是否在缺数时失败、是否拒绝越权。它不衡量投资收益。

优化循环不能通过以下方式提高分数：

- 更换或绕过 tick-stock-panel。
- 读取裁判文件。
- 扩大 Token scope。
- 把参考答案写进技能或记忆。

## 证据

每轮至少留下：任务标识、候选差异、执行摘要、采纳或回退原因、分数和运行标识。字段细节属于 REQ-008，现在不实现存储格式。
