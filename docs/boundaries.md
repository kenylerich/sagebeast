# 实现边界

这些边界在需求被接受后仍然有效。某条需求如果要求越过边界，先改本文件和对应决策记录，再实现。

## 运行时

- 不在本仓库维护 DeepSeek Harness 的 fork。
- 不复制 `agent-loop`、工具注册表或会话日志。
- 上游缺能力时，先开 Research，确认应上游修复、本仓库插件，还是明确不做。
- 插件卸载后不能留下交易权限、缓存口径或后台拉数任务。

## 数据

- 不直接调用 TickFlow、券商或其他行情厂商。
- 不读取 tick-stock-panel 的 Parquet、DuckDB 或内部服务模块。
- 不在 Sagebeast 里重算复权、涨跌停或换手率。需要这些字段时，向网关要已经按它的契约生产好的结果。
- 不把「数值小于 1 就乘 100」当作单位转换。
- 网关缺少能力时失败并说明缺什么。禁止静默换源。

## 自优化

- 不把 JobBench、LAB 或 WorkBuddy-Bench 的分数当作 Sagebeast 的验收。
- 不把 Harness² 的 OpenCode 或 Codex substrate 当作运行时。
- 提议阶段不能读取裁判标准或参考答案。
- 经验库只保存被采纳的 harness 和有执行证据支持的教训。没有证据的模型自述不入库。
- 优化器不能修改数据平面口径，也不能扩大 scope。

## 安全

- 研究输出必须带数据时间。没有时间的数字不能当成结论。
- `paper:trade` 和 `admin` 不在默认 Token 里。
- 实盘交易不在路线图内。以后若要讨论，必须是新的决策记录，不能塞进研究需求。

## 流程

- 未列入 `docs/decisions/0003-catalog-accepted.md` 的需求不能开工。
- 文档 PR 不能夹带可执行的产品实现。
- 跨仓库 Issue 引用不能代替本仓库 Issue。
