# 开放问题

只保留会改变实现选择的问题。已经由对话和代码定下来的，不放在这里。

## 已经听清的

- 产品是 App。任意页面打开 DeepSeek Harness，而不是只做一个聊天网站。
- 对话要能写策略代码、分析数据，并使用 `AGENTS.md`、skills、MCP。
- 策略执行与定时叫醒分开。并发和长任务在运行器里。
- Harness² 优化本仓库装进 DeepSeek Harness 的表面，不训练模型，不用外部基准当分数。
- 数据入口仍是 tick-stock-panel。不改三个上游的核心。
- 第一关注点是基本面策略的设计和复用，不是技术面扫描。

## Q1. App 怎样接上 DeepSeek Harness

挡住：REQ-002 的实现，不挡住需求本身。

代码事实：DeepSeek Harness 有 `web`、`headless`、`sdk`、`acp` profile，没有可嵌进外部 React 应用的抽屉组件。tick-stock-panel 的抽屉是它自己的扩展。

可选做法：

1. Sagebeast 自己画页面，对话区连接正在运行的 `dsh` 会话。
2. Sagebeast 的页面做成 DeepSeek Harness 的客户端插件，对话用它自己的 Web。

两种都能满足「任意页面打开对话」。它们的构建和清晰度成本不同。审阅时需要选一个，或者明确授权实现阶段再选。

## Q2. 第一版标的范围

挡住：REQ-003 以外的资产，以及 REQ-009 的页面字段。

代码事实：面板有股票、ETF、指数。财务因子只覆盖股票。没有可转债和期货的数据契约，模拟盘计划也明确不做期货。

建议：第一版只做股票基本面。ETF 先显示「没有基本面契约」。可转债和期货留到新的数据需求，不在策略运行器里伪造字段。

## Q3. 长周期指哪一种

挡住：REQ-012 和 REQ-013 的验收样本。

目前按两种都保留：

- 策略窗口跨多个报告期。这是策略代码的参数。
- 一次运行可能持续几小时。这是运行器的任务，不是一条提醒。

如果实际只指其中一种，审阅时删掉另一种，避免第一版做宽。
