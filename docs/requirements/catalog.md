## 听懂的产品

Sagebeast 是一个 App，用法跟 tick-stock-panel 一样：页面用来看数据和设计策略，任意页面都能打开 DeepSeek Harness 对话。对话能创建策略、分析数据、普通交谈，也能写代码。

策略是代码。对话负责把它写进 Sagebeast 的策略目录。运行器负责并发执行和长时间任务。DeepSeek Harness 的定时负责到点叫醒，不代替运行器。

分析重心是基本面，不是技术面筛股。股票可以沿 tick-stock-panel 已有的财务和经营数据走。ETF、可转债、期货不是同一套财报，面板也还没有后两者的数据契约。

`AGENTS.md`、skills、MCP 用 DeepSeek Harness 现成能力。Harness² 用来优化这些 harness 表面，让同一个模型在基本面任务上变好。不训练模型，不改上游核心。

## REQ-001 三个平面不要合并

问题：把数据源、Agent 循环和自优化执行器写进一个应用后，无法解释结果来自口径、提示词还是执行器。

可观察结果：实现改动能指出它属于 App、DeepSeek Harness 消费、tick-stock-panel 消费，还是 Harness² 方法。越界改动在审查时拒绝。

验收：

- 不 fork 三个上游，不把它们的源码复制进本仓库。
- 不读取面板的 Parquet 或内部服务对象。
- 不把 OpenCode 或 Codex 当作 Sagebeast 的执行器。

非目标：本条不选择 App 怎样连接 DeepSeek Harness 进程。

## REQ-002 任意页面打开 DeepSeek Harness

问题：tick-stock-panel 的助手不是 Harness。Sagebeast 的操作入口必须是 DeepSeek Harness 会话。

可观察结果：在策略、标的、结果任一页面，都能打开同一个 Harness 对话。对话能看见当前页面的标的或策略，并能写文件、读 `AGENTS.md`、加载 skill。

验收：

- 对话使用本机 `dsh`，不另写 Agent 循环。
- 关闭对话后面板仍在，已写的策略文件还在。
- 卸载或停用 Sagebeast 的 preset 后，它注册的工具和提示片段消失。

非目标：不把 DeepSeek Harness 的整站 Web 界面替换成 tick-stock-panel 的克隆。装载方式见开放问题 Q1。

## REQ-003 数据只经 tick-stock-panel

问题：自建行情和财务客户端会分裂复权、公告日和单位口径。

可观察结果：股票和已支持的 ETF 数据来自面板开放网关或它自带的 MCP。失败时保留状态码和错误正文，不换源。

验收：

- 默认 Token 不含 `paper:trade` 和 `admin`。
- 财务字段保持面板的公告日点时口径，不用数值大小猜测单位。
- 仓库里没有厂商 SDK，也没有可转债或期货的虚构接口。
- 测试使用录制响应或假网关，不提交 Token。

非目标：不在本条补齐面板没有的资产。那是 Q2。

## REQ-004 非投顾和权限边界

问题：自动分析容易被说成荐股或交易入口。

可观察结果：输出带数据时间，拒绝买卖指令。工具列表里没有下单工具。

验收：

- 提示或护栏写明不承诺收益。
- 价格和财务数字能追溯到一次网关调用。
- 安全测试不包含真实账户或可复用 Token。

非目标：不做合规页面，不做实盘通道。

## REQ-009 App 页面围着基本面策略

问题：现有面板的主路径是技术指标、扫描和回测。需要的是先设计基本面策略，再反复使用。

可观察结果：打开 App 后，能看到自己关心的标的、已保存的基本面策略，以及最近一次运行结果。技术面 K 线不是首页主角。

验收：

- 策略卡片展示名称、适用资产、最近运行时间和失败原因。
- 股票策略能引用财务或经营字段。字段缺失时显示缺口，不回退成均线策略。
- 页面不要求用户先写 Python 才能看懂策略在做什么。代码在对话和文件里，摘要在页面上。

非目标：不移植连板、异动、涨停监控作为第一屏。

## REQ-010 界面清晰，不默认发虚

问题：面板在页面缩放和 canvas 图表上会发虚，毛玻璃也加重合成负担。看着难受。

可观察结果：常见系统缩放下，正文、表格和图表边缘清楚。不需要贴近视屏幕才能读数字。

验收：

- 不用整页 `transform: scale` 放大后再拉伸 canvas。
- 图表按设备像素比绘制，放大后不比正文更糊。
- 背景模糊不是默认表面。信息层背后有图时，不开启会让图发虚的模糊。

非目标：不规定品牌色。不要求复刻某一款行情软件。

## REQ-011 用对话编写并登记策略代码

问题：策略要编码才能复用，但不应让人离开页面去另一个编辑器找目录。

可观察结果：在任意页面打开对话，说明一条基本面规则，对话把策略写成文件并登记。之后页面能选中它，再次运行不用重写。

验收：

- 生成文件只进入 Sagebeast 的策略目录。
- 对话不能修改 DeepSeek Harness 核心，也不能修改 tick-stock-panel 的内置策略目录。
- 策略文件有稳定 id、名称、适用资产和入口。缺字段时登记失败，并在对话里说明原因。
- 同一策略再次生成时更新原文件或明确另存，不悄悄覆盖无关策略。

非目标：不把 tick-stock-panel 的 Polars 策略格式原样当成 Sagebeast 格式。格式在实现时单独立约，但必须是代码文件。

## REQ-012 策略运行器负责并发和长任务

问题：一百只标的如果各开一个模型对话，费用和失败都不可控。一次扫描也可能超过一次对话的等待时间。

可观察结果：运行策略时，标的并行取数和计算。对话可以查看进度、读取结果和取消。取消后不把半成品标成成功。

验收：

- 默认并发发生在策略代码里，不是每个标的一个模型会话。
- 运行器通过面板网关取数，单标的失败不影响其他标的，结果里能看到失败原因。
- 长任务在 App 或宿主重启前有可查询的运行 id。重启后至少能看到上次是中断还是完成。
- 模型只在编排和解释时被调用。纯计算不为了并发去刷模型。

非目标：不保证全市场毫秒级扫描。第一版范围是用户关心的标的集合。

## REQ-013 定时叫醒，不假装任务已完成

问题：需要每天、每周或财报季后自动跑已保存策略。DeepSeek Harness 的提醒只负责把指令送回会话。

可观察结果：到点后，主会话收到「运行某策略」的指令，并启动 REQ-012 的运行器。页面能看到这次是定时触发的。

验收：

- 定时挂在主会话，不挂在子代理会话。这是 DeepSeek Harness 的现有限制。
- 宿主没开时不假装已经跑过。重新打开后，最多补最近一次错过的叫醒，并标明错过了几次。
- 提醒入队和运行完成是两条记录。只有运行器写完结果，页面才显示完成。
- 删除定时后，不再创建新运行。已经在跑的任务要单独取消。

非目标：不把 DeepSeek Harness 的 schedule 存储改成通用任务队列。

## REQ-014 AGENTS.md、skills、MCP 作为扩展面

问题：基本面方法、数据入口和编码规矩如果散落在提示词里，下次对话会丢。

可观察结果：工作区 `AGENTS.md` 告诉对话策略目录和禁止事项。skill 装载基本面写作步骤。MCP 连接 tick-stock-panel，对话能看见工具名和错误。

验收：

- 不另做第二套技能或插件系统。
- 未配置 MCP 时，对话说明缺少数据入口，不用网页搜索充当行情。
- skill 正文改完后，下一次加载用新文件。不要求重启上游核心。
- Token 不写进 `AGENTS.md` 或 skill。

非目标：不在本条决定第一个 skill 的段落结构。那要等一条真实策略被接受。

## REQ-005 基本面任务的跑分契约

问题：没有固定任务和独立裁判，就无法判断 harness 优化是改进还是运气。

可观察结果：同一组基本面任务可以重复运行，并得到可比分数和失败清单。

验收：

- 任务对执行器可见。评分标准在提议和探测阶段不可见。
- 分数检查是否取对字段、是否标明数据时间、缺数时是否失败、是否拒绝越权。
- 不使用收益、夏普或涨停命中率当分数。
- 不使用 JobBench、LAB 或 WorkBuddy 的题目和分数。

非目标：不在契约被接受前实现优化循环。

## REQ-006 用 Harness² 方法优化本仓库 harness

问题：手改提示词不能说明哪次修改让基本面任务变好。

可观察结果：给定预算，循环对同一任务提议、探测和组合 harness 修改，并留下执行对比。

验收：

- 执行会话是 REQ-002 的 DeepSeek Harness 路径。
- 可修改表面只包括 `AGENTS.md`、护栏、技能、工具说明、子代理说明和 Sagebeast 插件配置。
- 无效提议有限次重试后继承当前 harness。
- 优化器不能改变 Token scope、数据口径或策略运行器的计算结果。
- 模型权重不变。

非目标：不保证分数上升。不移植 Harness² 的执行器。

## REQ-008 优化实验可复现

问题：优化如果只发生在会话里，事后无法复核。

可观察结果：一次优化有独立记录，包含任务、候选 harness、执行证据、采纳或回退原因和分数。

验收：

- 相同任务集、预算、模式和种子能定位到同一次记录。
- 记录不含 Token 或模型密钥。
- 没有执行证据的教训不会被后续任务读取。
- 报告只读记录，不重新调用模型。

非目标：不建立公开排行榜。
