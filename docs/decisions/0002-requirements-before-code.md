# 0002. 需求接受前不写产品代码

状态：生效。

## 背景

仓库在建立需求管理之前是空的。运行时、数据入口和自优化方法都有现成上游，但装载方式、首个任务域和权限还没有接受记录。先写代码会把未决选择固化进目录结构。

## 决定

在 `docs/decisions/0003-catalog-accepted.md` 出现之前：

- 允许文档、决策记录、Issue 模板、标签、策略脚本和编码门禁。
- 不允许产品目录和可执行的产品实现。
- 需求目录里的条目都是草案。草案不是开工许可。
- 可以开 Issue 讨论文档和流程。不要开实现类 PR。

门禁脚本是 [coding-gate.mjs](../../.github/issue-management/coding-gate.mjs)。它只检查顶层路径。把实现藏进 `docs/` 同样违反本决定，审查时拒绝。

## 怎样解除

维护者把接受范围写入 `docs/decisions/0003-catalog-accepted.md`。文件必须列出接受的需求编号，以及仍然开放的问题。没有列出的编号不能实现。

口头同意或聊天记录不算接受记录。接受记录本身是文档 PR，引用跟踪这个决定的 Issue。

## 后果

阶段 0 可以合并文档和流程，但不能提前放进客户端、插件骨架或实验脚本。骨架也是产品代码。
